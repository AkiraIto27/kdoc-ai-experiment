## 集計と検証の範囲

時計基準を満たす対象観測400件、CLI完了401回、実試行404回です。未完了3回と時計不適合の完了1回を別記し、test dataへ混ぜません。除外した既知usageはprivate証拠に保持し、消去・0補完・時間補正はしていません。

計測中のcapacityで完了情報を取得できないケースは、失敗記録を保持して再試行します。提出物の有無で品質を選別せず、partialコードは採点前に保存します。この運用方針は計測開始後に拡張しました。 2026-11-01にユーザーが各条件100件の完了した有効計測を分母に選びました。品質・token・時間はこの対象に条件付きの値です。timeoutはhost suspensionと併存しましたが、sleepがなければ600秒以内に完了したという因果は証明していません。再開時はAC確認・蓋を開く確認と一時sleep assertionを実行条件とし、永続設定は変更しません。 時計差1.0秒の基準は事前に固定しましたが、指定1件の除外・再計測という扱いは違反を観測した後、採点と再計測の前に追加した運用変更です。完全に事前登録した再標本化方針とは扱いません。内容・品質は選別に使っていません。600対象観測の品質・token・時間は条件付きであり、全実試行の成功率や総資源消費ではありません。

固定11チェックの合格率は有効なCLI計測の提出物に対する値であり、混雑で未完了になった試行は実試行数・失敗件数として別記します。

キャッシュは有効のまま無効化していません。cached inputはinputの内数です。cache率はΣcached_input_tokens / Σinput_tokensのトークン加重比率で、リクエストのcache hit率ではありません。

同じ課題を `gpt-6.1-sol / xhigh`、CLI `codex-cli 0.162.0-alpha.2`、並列度1で実行しました。毎回新しい初期コピーと会話です。採点は別コンテキストの固定11チェックを使います。採点不合格を理由に本集計器が試行を選び直すことはありません。

今回の①②③⑥の測定区間（UTC）は `2026-10-30T07:03:50.453801+00:00` から `2026-11-01T17:38:54.219567+00:00`。保持した200件とは計測時期が異なります。サーバー負荷・キャッシュ・接続通知の影響を分離できないため、因果や統計的有意差は主張しません。元のCLI時間を補正せず使用します。

共通初期コードはKtor MockEngine、採点はテスト用Repositoryを使用し、外部の商品HTTP API実験ではありません。Skillは⑥のKDoc生成時だけ使いました。

JSONの `historical_n` / `historical_conditions` は今回保持した200件、`additional_recorded_n` / `additional_cohort_conditions` は今回再測定した400件を表します。旧①②③⑥の行・平均値を集計へ混在させません。新しい測定manifest・計測集計・独立採点集計のSHA-256をJSONの `batches` に記録します。
