# ②・③・⑤のKDoc比較用variant

実測①に使ったAの初期ソースを複製し、KDocだけを変えた3条件です。この文書の作成時点では、新しい3条件のLLM実測は未実施です。既存の[①/A](../../conditions/A/)と[④/E](../../conditions/E/)は変更していません。

| 条件 | 場所 | KDocの情報 |
| --- | --- | --- |
| ② | [number2](../../conditions/number2/) | 名前・型を言い換える自明な要約とparam/return短文。境界・例外などの契約を追加しない |
| ③ | [number3](../../conditions/number3/) | 既存④/Eの仕様事項を保ち、表現を短くした契約 |
| ⑤ | [number5](../../conditions/number5/) | ③の全文に、資料で確認できる設計理由・ドメイン背景を追加 |

各条件の同じ5ファイル・18箇所にKDocを付けています。挿入したKDoc行を除くと①/Aのbyte列と一致し、実装・データ・通常テスト・設定を変えていません。テンプレート由来のテストKDocは全条件で共通です。

③と④の18箇所について、87個の仕様事項の対応を[specification-map.json](specification-map.json)に記録しました。これはAPIの既存記述の対応表で、採点条件や課題の期待解ではありません。⑤は③のKDoc本文をそのまま保ち、5箇所にだけ[根拠付き背景](background-evidence.json)を追記しています。完成回答や実装例は追加していません。

⑤で加えた背景は、パッケージによる責務分離、domain層の依存方向、再現性のための固定JSONとMockEngine、StateFlowと明示的な追加取得の採用理由、架空の備品カタログの表示内容です。既定50件・上限100件という数値を選んだ理由は資料に明記されていないため、性能や通信負荷が理由だとは記載していません。

| KDocの記述量 | ② | ③ | ⑤ | 歴史対照④/E |
| --- | ---: | ---: | ---: | ---: |
| 文字数（コメント記号・改行を含む） | 1,172 | 2,715 | 3,090 | 3,180 |
| UTF-8 bytes | 1,684 | 5,199 | 6,018 | 6,546 |

記述量はソースの大きさであり、モデルのtoken数ではありません。③は④よりUTF-8 bytesで約21%短くなっています。

APIは[API.md](API.md)、条件別ファイルhashは[source-manifest.json](source-manifest.json)、追加KDocは[number2](number2-kdoc.diff)・[number3](number3-kdoc.diff)・[number5](number5-kdoc.diff)のdiffで確認できます。

公開版は各67ファイルです。実測時の初期コピー各73ファイルから、元の公開A/Eと同じ共通`.tools/`6ファイルを除外しています。端末固有のJDK/Kotlinパスを使う補助ツールと同梱JAR、非公開採点器、生会話、認証情報、課題の完成回答は公開しません。通常テストとREADMEは①と同じ内容で、KDoc以外から契約を読める条件も保持されています。

新しい比較は②・③・⑤を各20試行、同じprompt・gpt-6.1-sol/xhigh・独立した初期コピーと会話で実行する計画です。条件順は開始前に固定し、wrapperによる再試行・除外・差替えは行いません。CLIは0.162.0-alpha.2を使用し、内部provider retryは既定のまま記録します。実際のモデルrevisionは不明です。

この3条件は①と同じKtor MockEngine経路を使います。PagesのソケットHTTPを使う条件とは別実験です。旧①/④を再実施したとは扱わず、旧CLIとの差もあるため、新しい3条件と歴史対照を分けて報告します。同じ1課題の反復であり、60種類の独立した課題ではありません。
